# Deploy Manager

在 Windows + nginx 环境下，给前端项目做「不可变版本发布」的小工具，体验类似 Vercel：
每次部署生成一个独立的版本目录，通过切换一个目录联接点（junction）在版本间秒级切换，
可以随时回滚，也可以看到每个版本的部署时间和更新说明。

## 原理

每个项目在服务器上对应一个目录，结构如下：

```
D:\sites\my-project\
  releases\
    20260818-153042-a1b2c3\   <- 某次部署解压出来的静态文件，之后不会再被修改
    20260817-120500-f4e5d6\
  current                     <- NTFS 目录联接点（junction），nginx 的 root 固定指向它
```

`current` 不是一个真实目录，而是一个指向 `releases\` 下某个文件夹的联接点。
**切换版本 = 把这个联接点重新指向另一个文件夹**，不需要复制/移动任何静态文件，
nginx 也不需要 reload——它是按请求实时解析路径的，新请求立刻会走到新版本。

之所以用 junction 而不是普通符号链接（symlink），是因为在 Windows 上创建目录联接点
**不需要管理员权限**，普通用户权限运行的 Node 进程就能创建，这也是这个工具能以最简单的方式
在你现有服务器上运行的关键。

## 安装

前提：服务器上已经装好 Node.js（建议 18+）。

```bash
cd deploy-manager
npm install
```

依赖都是纯 JS 库（express / multer / adm-zip / fs-extra），不需要额外装 C++ 编译工具链。

## 启动

双击 `start.bat`，或者：

```bash
node server.js
```

启动后访问 `http://服务器IP:3000` 即可，没有登录验证。

建议把这个服务用 [NSSM](https://nssm.cc/) 或 [pm2](https://pm2.keymetrics.io/)
注册成 Windows 服务/开机自启进程，这样服务器重启后也能自动恢复。

## 使用方法

1. **新建项目**：填写项目名称和一个服务器上的绝对路径（例如 `D:\sites\my-project`），
   这个目录会自动生成 `releases\` 子目录。
2. **配置 nginx**：把该项目 nginx 配置里的 `root` 指向 `<这个目录>\current`，例如：

   ```nginx
   server {
       listen 80;
       server_name example.com;
       root D:/sites/my-project/current;

       location / {
           try_files $uri $uri/ /index.html;
       }
   }
   ```

   （Windows 下 nginx 配置推荐用正斜杠 `/`）配置好后 reload 一次 nginx，之后就不用再动它了。

3. **部署新版本**：点"部署新版本"，选择打包好的 zip（`dist` 文件夹压缩成的 zip 也行，
   工具会自动识别并去掉多余的一层文件夹），填写这次更新了什么，点"开始部署"。
   默认部署完立即上线，也可以取消勾选先只上传不上线。
4. **回滚/切换版本**：时间线里点某个历史版本的"切换到此版本"，几乎是瞬间生效。
5. **删除/清理旧版本**：可以单个删除，也可以用"清理旧版本"一键只保留最近 N 个
   （当前线上版本无论如何都不会被清理掉）。
6. **修改项目**：在“项目设置”中可以修改名称和服务器目录。修改目录时只迁移工具管理的
   `releases` 并重建 `current`，新旧根目录里的其他文件不会移动。
7. **删除项目**：默认只从管理器移除项目，已有 `current` 和版本文件会继续保留；如果明确勾选
   “同时删除”，才会删除 `current` 联接点和 `releases` 目录。

## 一些需要注意的点

- **这个后台没有登录验证，谁能访问到这个端口谁就能删除/覆盖你的线上文件**，
  所以千万不要把 3000 端口暴露在公网或者路由器做端口转发。只在服务器本机用，
  或者只在你信任的内网/VPN 里访问。如果以后需要远程访问，比较简单的做法是
  用 SSH 隧道（`ssh -L 3000:localhost:3000 你的服务器`）转发过来，而不是直接开放端口。
- 上传大小上限默认 300MB，可以用环境变量 `MAX_UPLOAD_MB` 调整。
- 如果你的 nginx 开启了 `open_file_cache`，极少数情况下切换版本后可能会短暂看到
  旧文件被缓存的情况，建议对这类静态资源目录关闭该缓存，或缩短缓存时间。
- 版本元数据存在 `data/db.json` 里，是个普通 JSON 文件，方便你自己查看或备份。
- 当前版本是单用户使用的最小实现，没有做多用户权限、操作日志、HTTPS 之类的功能，
  如果需要可以在这个基础上继续扩展。
